---
title: "Attach Comment"
api: "POST https://api.velt.dev/v2/agents/checks/comments/attach"
---

Use this API to attach a comment a person wrote to a check. The attached comment counts in the check's open count and pages, lists under the check in [List Check Comments](/api-reference/rest-apis/v2/agents/checks/comments/list), and resolves and verifies with it. Attaching a comment that is already attached to another check moves it.

Only a person's comment can be attached. An agent comment already belongs to its check and is refused. The engine never attaches a comment on its own. See [Checks Overview](/api-reference/rest-apis/v2/agents/checks/overview#comment).

# Endpoint

`POST https://api.velt.dev/v2/agents/checks/comments/attach`

# Headers

<ParamField header="x-velt-api-key" type="string" required>
  Your API key.
</ParamField>

<ParamField header="x-velt-auth-token" type="string" required>
  Your [Auth Token](/security/auth-tokens).
</ParamField>

# Body

#### Params

<ParamField body="data" type="object" required>
  <Expandable title="properties">
    <ParamField body="organizationId" type="string" required>
      1 to 512 characters. The organization of the project.
    </ParamField>

    <ParamField body="documentId" type="string" required>
      1 to 512 characters. The document of the project.
    </ParamField>

    <ParamField body="annotationId" type="string" required>
      The person's comment annotation id. 1 to 512 characters, no `/`, and not `.` or `..`.
    </ParamField>

    <ParamField body="ruleKey" type="string" required>
      The check. `[a-z0-9:-]`, at most 120 characters.
    </ParamField>

    <ParamField body="userId" type="string" required>
      1 to 512 characters. Recorded as the person who attached the comment.
    </ParamField>
  </Expandable>
</ParamField>

The schema uses `.strict()`: unknown fields are rejected.

## **Example Requests**

```JSON
{
  "data": {
    "organizationId": "org_acme",
    "documentId": "acme-marketing-site",
    "annotationId": "H3vN6pQ1zT8kWmB5xYcR",
    "ruleKey": "link-broken",
    "userId": "user_sam"
  }
}
```

# Response

#### Success Response

```JSON
{
  "result": {
    "status": "success",
    "message": "Comment attached",
    "data": {
      "attached": true,
      "ruleKey": "link-broken"
    }
  }
}
```

| Field           | Type    | Description |
| --------------- | ------- | ----------- |
| `data.attached` | boolean | Always `true`. |
| `data.ruleKey`  | string  | The check the comment is now attached to. |

The comment's [`checkInfo`](/api-reference/sdk/models/data-models#checkinfo) now holds `attached: true` and `attachedRuleKey`.

#### Failure Response

```JSON
{
  "error": {
    "message": "An agent comment cannot be attached to or detached from a check",
    "status": "FAILED_PRECONDITION",
    "details": {
      "reason": "CHECKS_AGENT_COMMENT_NOT_ATTACHABLE"
    }
  }
}
```

**Errors:** `INVALID_ARGUMENT` (a body outside the schema: a missing or malformed `annotationId` or `ruleKey`, a missing `userId`, or an unknown field) / `NOT_FOUND` with `CHECKS_COMMENT_NOT_FOUND` (no such comment in the project) or `CHECKS_WORKSPACE_NOT_FOUND` (the workspace has no store database) / `FAILED_PRECONDITION` with `CHECKS_AGENT_COMMENT_NOT_ATTACHABLE` (an agent comment).
