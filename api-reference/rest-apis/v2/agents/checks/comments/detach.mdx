---
title: "Detach Comment"
api: "POST https://api.velt.dev/v2/agents/checks/comments/detach"
---

Use this API to detach a person's comment from the check it was [attached](/api-reference/rest-apis/v2/agents/checks/comments/attach) to. The comment's `checkInfo` is removed and the check's counts are updated. The comment itself, its status and its replies are not changed.

# Endpoint

`POST https://api.velt.dev/v2/agents/checks/comments/detach`

# Headers

<ParamField header="x-velt-api-key" type="string" required>
  Your API key.
</ParamField>

<ParamField header="x-velt-auth-token" type="string" required>
  Your [Auth Token](/security/auth-tokens).
</ParamField>

# Body

#### Params

<ParamField body="data" type="object" required>
  <Expandable title="properties">
    <ParamField body="organizationId" type="string" required>
      1 to 512 characters. The organization of the project.
    </ParamField>

    <ParamField body="documentId" type="string" required>
      1 to 512 characters. The document of the project.
    </ParamField>

    <ParamField body="annotationId" type="string" required>
      The attached comment's annotation id. 1 to 512 characters, no `/`, and not `.` or `..`.
    </ParamField>

    <ParamField body="userId" type="string" required>
      1 to 512 characters. The person who detaches the comment.
    </ParamField>
  </Expandable>
</ParamField>

The schema uses `.strict()`: unknown fields are rejected.

## **Example Requests**

```JSON
{
  "data": {
    "organizationId": "org_acme",
    "documentId": "acme-marketing-site",
    "annotationId": "H3vN6pQ1zT8kWmB5xYcR",
    "userId": "user_sam"
  }
}
```

# Response

#### Success Response

```JSON
{
  "result": {
    "status": "success",
    "message": "Comment detached",
    "data": {
      "detached": true
    }
  }
}
```

#### Failure Response

```JSON
{
  "error": {
    "message": "This comment is not attached to a check",
    "status": "FAILED_PRECONDITION",
    "details": {
      "reason": "CHECKS_COMMENT_NOT_ATTACHED"
    }
  }
}
```

**Errors:** `INVALID_ARGUMENT` (a body outside the schema: a missing or malformed `annotationId`, a missing `userId`, or an unknown field) / `NOT_FOUND` with `CHECKS_COMMENT_NOT_FOUND` (no such comment in the project) or `CHECKS_WORKSPACE_NOT_FOUND` (the workspace has no store database) / `FAILED_PRECONDITION` with `CHECKS_AGENT_COMMENT_NOT_ATTACHABLE` (an agent comment) or `CHECKS_COMMENT_NOT_ATTACHED` (the comment is not attached to a check).
