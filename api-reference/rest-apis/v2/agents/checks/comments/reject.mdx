---
title: "Reject Comment"
api: "POST https://api.velt.dev/v2/agents/checks/comments/reject"
---

Use this API to reject one comment of a check, with one of the four [reject reasons](/api-reference/rest-apis/v2/agents/checks/overview#reject-reasons). It writes the same shape as the Velt SDK's [`rejectSuggestion()`](/api-reference/sdk/api/api-methods#rejectsuggestion): the comment's `suggestion.status` becomes `rejected`, with `suggestion.rejectReason` (the person's words when given, else the reason), `suggestion.resolvedBy` and `suggestion.resolvedAt`, and the annotation becomes a regular comment.

The comment's status does not change: an Open comment stays Open, with its pin, and a Resolved one stays Resolved. A resolve that was waiting for its verify rescan stops waiting. Unlike the SDK, which rejects only a pending suggestion, this rejects any agent comment that is not rejected yet. A rejected comment counts nowhere: not in the check's open count, never makes a check failing, and not in the score. When an agent finds the same problem again, the comment stays rejected as it is: no scan reopens, resolves, verifies or rewrites it.

Reject is idempotent: a comment that is already rejected is left as it is.

The comment can be an agent comment, or a person's comment [attached](/api-reference/rest-apis/v2/agents/checks/comments/attach) to a check. A person's comment that is not attached to a check is refused.

# Endpoint

`POST https://api.velt.dev/v2/agents/checks/comments/reject`

# Headers

<ParamField header="x-velt-api-key" type="string" required>
  Your API key.
</ParamField>

<ParamField header="x-velt-auth-token" type="string" required>
  Your [Auth Token](/security/auth-tokens).
</ParamField>

# Body

#### Params

<ParamField body="data" type="object" required>
  <Expandable title="properties">
    <ParamField body="organizationId" type="string" required>
      1 to 512 characters. The organization of the project.
    </ParamField>

    <ParamField body="documentId" type="string" required>
      1 to 512 characters. The document of the project.
    </ParamField>

    <ParamField body="annotationId" type="string" required>
      The comment annotation id. 1 to 512 characters, no `/`, and not `.` or `..`.
    </ParamField>

    <ParamField body="reason" type="string" required>
      `"wrong"`, `"not_important"`, `"not_applicable"` or `"cannot_tell"`.
    </ParamField>

    <ParamField body="userId" type="string" required>
      1 to 512 characters. Recorded as the person who rejected the comment.
    </ParamField>

    <ParamField body="feedbackReason" type="string">
      At most 2,000 characters. The person's own words, stored as `suggestion.rejectReason` and sent with the reason to the agent's feedback.
    </ParamField>
  </Expandable>
</ParamField>

The schema uses `.strict()`: unknown fields are rejected.

## **Example Requests**

```JSON
{
  "data": {
    "organizationId": "org_acme",
    "documentId": "acme-marketing-site",
    "annotationId": "K7mQ2xR9vB4wLdT1sYpN",
    "reason": "not_applicable",
    "userId": "user_sam",
    "feedbackReason": "This link is behind a login on purpose."
  }
}
```

# Response

#### Success Response

```JSON
{
  "result": {
    "status": "success",
    "message": "Comment rejected",
    "data": {
      "rejected": true
    }
  }
}
```

#### Failure Response

```JSON
{
  "error": {
    "message": "Only an agent comment can be resolved, rejected or reopened here",
    "status": "FAILED_PRECONDITION",
    "details": {
      "reason": "CHECKS_NOT_AGENT_COMMENT"
    }
  }
}
```

**Errors:** `INVALID_ARGUMENT` (a body outside the schema: a missing `annotationId` or `userId`, a `reason` outside the four (`excluded`, which a row can show, is the engine's own and refused here), a `feedbackReason` over 2,000 characters, or an unknown field) / `NOT_FOUND` with `CHECKS_COMMENT_NOT_FOUND` (no such comment in the project) / `FAILED_PRECONDITION` with `CHECKS_NOT_AGENT_COMMENT` (a person's comment not attached to a check).
