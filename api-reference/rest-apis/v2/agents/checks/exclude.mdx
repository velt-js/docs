---
title: "Exclude Check"
api: "POST https://api.velt.dev/v2/agents/checks/exclude"
---

Use this API to exclude a check for a project, with one of the four [reject reasons](/api-reference/rest-apis/v2/agents/checks/overview#reject-reasons). The check's state becomes `excluded`:

- it leaves the score (its `scoreImpact` is `0`);
- its open comments are [rejected](/api-reference/rest-apis/v2/agents/checks/comments/reject) with the reason `excluded`. Their status does not change;
- its findings write no comment. The agent still runs.

[Include Check](/api-reference/rest-apis/v2/agents/checks/include) undoes it.

# Endpoint

`POST https://api.velt.dev/v2/agents/checks/exclude`

# Headers

<ParamField header="x-velt-api-key" type="string" required>
  Your API key.
</ParamField>

<ParamField header="x-velt-auth-token" type="string" required>
  Your [Auth Token](/security/auth-tokens).
</ParamField>

# Body

#### Params

<ParamField body="data" type="object" required>
  <Expandable title="properties">
    <ParamField body="organizationId" type="string" required>
      1 to 512 characters. The organization of the project.
    </ParamField>

    <ParamField body="documentId" type="string" required>
      1 to 512 characters. The document of the project.
    </ParamField>

    <ParamField body="ruleKey" type="string" required>
      The check. `[a-z0-9:-]`, at most 120 characters.
    </ParamField>

    <ParamField body="reason" type="string" required>
      `"wrong"`, `"not_important"`, `"not_applicable"` or `"cannot_tell"`.
    </ParamField>

    <ParamField body="userId" type="string" required>
      1 to 512 characters. Recorded as the person who excluded the check.
    </ParamField>
  </Expandable>
</ParamField>

The schema uses `.strict()`: unknown fields are rejected.

## **Example Requests**

```JSON
{
  "data": {
    "organizationId": "org_acme",
    "documentId": "acme-marketing-site",
    "ruleKey": "link-unlinked-email",
    "reason": "not_important",
    "userId": "user_sam"
  }
}
```

# Response

#### Success Response

```JSON
{
  "result": {
    "status": "success",
    "message": "Check excluded",
    "data": {
      "excluded": true
    }
  }
}
```

#### Failure Response

```JSON
{
  "error": {
    "message": "Workspace not found or has no store database for the checks engine",
    "status": "NOT_FOUND",
    "details": {
      "reason": "CHECKS_WORKSPACE_NOT_FOUND"
    }
  }
}
```

**Errors:** `INVALID_ARGUMENT` (a body outside the schema: a missing or malformed `ruleKey`, a `reason` outside the four, a missing `userId`, or an unknown field) / `NOT_FOUND` with `CHECKS_WORKSPACE_NOT_FOUND` (the workspace has no store database).
