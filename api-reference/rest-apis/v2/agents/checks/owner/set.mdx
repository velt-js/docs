---
title: "Set Check Owner"
api: "POST https://api.velt.dev/v2/agents/checks/owner/set"
---

Use this API to set a check's owner for a project, or to clear it with `null`. Without an owner set here, the check's owner is the default owner for its responsibility, else the project admin (see [Update Check Settings](/api-reference/rest-apis/v2/agents/checks/settings/update)). [List Checks](/api-reference/rest-apis/v2/agents/checks/list) returns both: `ownerMemberId` (set here) and `effectiveOwner` (the one that applies).

# Endpoint

`POST https://api.velt.dev/v2/agents/checks/owner/set`

# Headers

<ParamField header="x-velt-api-key" type="string" required>
  Your API key.
</ParamField>

<ParamField header="x-velt-auth-token" type="string" required>
  Your [Auth Token](/security/auth-tokens).
</ParamField>

# Body

#### Params

<ParamField body="data" type="object" required>
  <Expandable title="properties">
    <ParamField body="organizationId" type="string" required>
      1 to 512 characters. The organization of the project.
    </ParamField>

    <ParamField body="documentId" type="string" required>
      1 to 512 characters. The document of the project.
    </ParamField>

    <ParamField body="ruleKey" type="string" required>
      The check. `[a-z0-9:-]`, at most 120 characters.
    </ParamField>

    <ParamField body="ownerMemberId" type="string | null" required>
      The owner's user id (1 to 512 characters), or `null` to clear the owner. The field must be present.
    </ParamField>

    <ParamField body="owner" type="object | null">
      The owner's name and email, so they show without a lookup: `{ userId, name?, email? }`, `name` and `email` at most 512 characters each. Kept only when `owner.userId` equals `ownerMemberId`.
    </ParamField>
  </Expandable>
</ParamField>

The schema uses `.strict()`: unknown fields, in `data` or in `owner`, are rejected.

## **Example Requests**

#### 1. Set the owner

```JSON
{
  "data": {
    "organizationId": "org_acme",
    "documentId": "acme-marketing-site",
    "ruleKey": "link-broken",
    "ownerMemberId": "user_jordan",
    "owner": {
      "userId": "user_jordan",
      "name": "Jordan Lee",
      "email": "jordan@example.com"
    }
  }
}
```

#### 2. Clear the owner

```JSON
{
  "data": {
    "organizationId": "org_acme",
    "documentId": "acme-marketing-site",
    "ruleKey": "link-broken",
    "ownerMemberId": null
  }
}
```

# Response

#### Success Response

```JSON
{
  "result": {
    "status": "success",
    "message": "Check owner set",
    "data": {
      "ownerMemberId": "user_jordan"
    }
  }
}
```

| Field                | Type           | Description |
| -------------------- | -------------- | ----------- |
| `data.ownerMemberId` | string \| null | The owner now set, or `null` when cleared. |

#### Failure Response

```JSON
{
  "error": {
    "message": "Workspace not found or has no store database for the checks engine",
    "status": "NOT_FOUND",
    "details": {
      "reason": "CHECKS_WORKSPACE_NOT_FOUND"
    }
  }
}
```

**Errors:** `INVALID_ARGUMENT` (a body outside the schema: a missing or malformed `ruleKey`, a missing `ownerMemberId`, an `owner` without `userId`, or an unknown field) / `NOT_FOUND` with `CHECKS_WORKSPACE_NOT_FOUND` (the workspace has no store database).

<ResponseExample>
```js
{
  "result": {
    "status": "success",
    "message": "Check owner set",
    "data": {
      "ownerMemberId": null
    }
  }
}
```
</ResponseExample>
