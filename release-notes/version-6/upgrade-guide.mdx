## Overview
- **Key changes in this series**:
  - `onContactSelected()` emits for every contact selection, so handlers that assumed a pre-filtered signal need their own filter.

## Breaking Changes

- [**Contact Selection**] `onContactSelected()` and `useContactSelected()` now fire for every contact selected from the contact dropdown.
  - Previously the event fired only when the selected contact had no `userId`, or when the document was `restricted` and the contact was not a document member.
  - If your handler assumed the contact had no access to the document, filter on `documentAccessType` and `isDocumentContact` yourself.
  - Every event now carries `isOrganizationContact` and `isDocumentContact`, computed from the organization and document contact lists.

**Before:**

<Tabs>
<Tab title="React / Next.js">
```jsx
// Hook
const selectedContact = useContactSelected();

useEffect(() => {
  if (selectedContact) {
    showNoAccessWarning(selectedContact.contact);
  }
}, [selectedContact]);

// API Method
const contactElement = client.getContactElement();
const subscription = contactElement.onContactSelected().subscribe((payload) => {
  showNoAccessWarning(payload.contact);
});
subscription?.unsubscribe();
```
</Tab>
<Tab title="Other Frameworks">
```js
const contactElement = Velt.getContactElement();
const subscription = contactElement.onContactSelected().subscribe((payload) => {
  showNoAccessWarning(payload.contact);
});
subscription?.unsubscribe();
```
</Tab>
</Tabs>

**After:**

<Tabs>
<Tab title="React / Next.js">
```jsx
// Hook
const selectedContact = useContactSelected();

useEffect(() => {
  if (selectedContact?.documentAccessType === 'restricted' && !selectedContact.isDocumentContact) {
    showNoAccessWarning(selectedContact.contact);
  }
}, [selectedContact]);

// API Method
const contactElement = client.getContactElement();
const subscription = contactElement.onContactSelected().subscribe((payload) => {
  if (payload.documentAccessType === 'restricted' && !payload.isDocumentContact) {
    showNoAccessWarning(payload.contact);
  }
});
subscription?.unsubscribe();
```
</Tab>
<Tab title="Other Frameworks">
```js
const contactElement = Velt.getContactElement();
const subscription = contactElement.onContactSelected().subscribe((payload) => {
  if (payload.documentAccessType === 'restricted' && !payload.isDocumentContact) {
    showNoAccessWarning(payload.contact);
  }
});
subscription?.unsubscribe();
```
</Tab>
</Tabs>

## How to Upgrade
### Upgrade Manually
1. Update your Velt packages to `6.0.0`.
2. Search your app for `onContactSelected` and `useContactSelected`.
3. For each handler that treated the event as a "contact has no access" signal, add the filter `documentAccessType === 'restricted' && !isDocumentContact`.
4. Deploy the latest version of the Velt SDK to your product.

<Note>
If your handler already inspects `documentAccessType`, `isOrganizationContact`, or `isDocumentContact` before acting, no changes are required.
</Note>

### Upgrade using AI

Use this prompt to update your contact selection handlers.

```
Update every Velt contact selection handler in this codebase.

Velt v6.0.0 changed `onContactSelected()` and `useContactSelected()` to emit for
every contact selection. Before v6.0.0 they emitted only when the selected contact
had no `userId`, or when the document access type was `restricted` and the contact
was not a document member.

SCOPE: only handlers subscribed to `onContactSelected()` or reading the value
returned by `useContactSelected()`.

For each handler:
1. If the handler acts on the contact unconditionally, and that action assumes the
   contact lacks document access (for example showing an invite or no-access
   warning), guard it with:
   `payload.documentAccessType === 'restricted' && !payload.isDocumentContact`
2. If the handler already checks `documentAccessType`, `isOrganizationContact`, or
   `isDocumentContact`, leave it unchanged.

Do NOT modify any other Velt event subscriptions.
```
