## Breaking Changes

### React: `VeltCommentsSidebarV2`'s `embedMode` prop is now `boolean`

`IVeltCommentSidebarV2Props.embedMode` changed from `string` to `boolean`. Code that passed a string literal no longer type-checks. The prop is now serialized through the same conversion every other boolean prop on this component uses, so the boolean you pass actually reaches the element.

**Before:**

<Tabs>
<Tab title="React / Next.js">
```tsx
// embedMode?: string
<VeltCommentsSidebarV2 embedMode="true" />
```
</Tab>
<Tab title="Other Frameworks">
```html
<velt-comments-sidebar-v2 embed-mode="true"></velt-comments-sidebar-v2>
```
</Tab>
</Tabs>

**After:**

<Tabs>
<Tab title="React / Next.js">
```tsx
// embedMode?: boolean
<VeltCommentsSidebarV2 embedMode={true} />
```
</Tab>
<Tab title="Other Frameworks">
```html
<velt-comments-sidebar-v2 embed-mode="true"></velt-comments-sidebar-v2>
```
</Tab>
</Tabs>

<Note>
If you were already passing `embedMode={true}` with a `@ts-ignore` or through an untyped spread, no source change is needed. That call site now type-checks and the prop starts reaching the element. The HTML/Vanilla `embed-mode` attribute is unchanged; it still takes a string.
</Note>

### `selectedAnnotationsLocationMap` no longer carries a comment tool's context hash

For an annotation created by a `VeltCommentTool` configured with `context`, `folderId`, `documentId`, or `locationId`, `selectedAnnotationsLocationMap` used to hold a context hash for that annotation. That hash now lives on an internal channel and is not exposed to wireframes, so the entry reads `undefined` until a pin or bubble claims the selection. Entries written by an actual surface (a pin portal, a `VeltCommentPin`, a bubble, or an inline-section component id) are unchanged.

**Before:**

```js
// annotation created via <velt-comment-tool context={...}>
selectedAnnotationsLocationMap['ann-1'] // → '198a37d23341a5034b50e475790901e3'
```

**After:**

```js
selectedAnnotationsLocationMap['ann-1'] // → undefined, until a pin/bubble claims it
```

If you were reading a context hash out of `selectedAnnotationsLocationMap` to identify a comment tool's context, there is no wireframe-visible replacement for it in this release.

## How to Upgrade

1. Search your codebase for `VeltCommentsSidebarV2` usages that pass `embedMode` as a string literal and switch them to a boolean.
2. Search custom wireframes for reads of `selectedAnnotationsLocationMap` and confirm they don't depend on a comment tool's context hash showing up there.
3. Deploy the latest version of the Velt SDK to your product.
