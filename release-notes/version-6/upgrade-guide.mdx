## Breaking Changes

### `isAssigneeChanged` required on `AddCommentEvent`, `AddCommentAnnotationEvent`, and `UpdateCommentEvent`

As of `6.0.15`, `@veltdev/types` requires `isAssigneeChanged: boolean` on these three event interfaces. Events the SDK dispatches always include it, so code that only reads event data needs no change. TypeScript code that builds one of these objects directly, for example a test mock, must now set the field.

**Before:**

<Tabs>
<Tab title="React / Next.js">
```tsx
const mockEvent: AddCommentEvent = {
  annotationId: 'ANNOTATION_ID',
  commentAnnotation,
  commentId: 1,
  comment,
  metadata,
};
```
</Tab>
<Tab title="Other Frameworks">
```ts
const mockEvent: AddCommentEvent = {
  annotationId: 'ANNOTATION_ID',
  commentAnnotation,
  commentId: 1,
  comment,
  metadata,
};
```
</Tab>
</Tabs>

**After:**

<Tabs>
<Tab title="React / Next.js">
```tsx
const mockEvent: AddCommentEvent = {
  annotationId: 'ANNOTATION_ID',
  commentAnnotation,
  commentId: 1,
  comment,
  metadata,
  isAssigneeChanged: false,
};
```
</Tab>
<Tab title="Other Frameworks">
```ts
const mockEvent: AddCommentEvent = {
  annotationId: 'ANNOTATION_ID',
  commentAnnotation,
  commentId: 1,
  comment,
  metadata,
  isAssigneeChanged: false,
};
```
</Tab>
</Tabs>

The same field is required on `AddCommentAnnotationEvent` and `UpdateCommentEvent`. [Learn more →](/api-reference/sdk/models/data-models#addcommentevent)

## How to Upgrade

Update to `@veltdev/sdk@6.0.15` and the matching `@veltdev/react` version. No runtime change is required. If your TypeScript code constructs an `AddCommentEvent`, `AddCommentAnnotationEvent`, or `UpdateCommentEvent` object directly, add `isAssigneeChanged`.
