Assign someone to the Velt app in Okta and they're added to your Velt workspace. Unassign or deactivate them and they're removed. Okta does this over SCIM 2.0, so nobody has to send invites.

- **Protocol:** SCIM 2.0
- **Setup time:** about 5 minutes
- **Your product:** the Velt SDK running in your product is not affected. This only changes who is a member of your Velt workspace.

## How it works

1. You turn on user sync in Velt and create a sync token.
2. You paste the token into the Velt app's **Provisioning** tab in Okta.
3. You choose what Okta sends: new users, profile changes and deactivations.
4. You assign people in Okta, and Okta adds them to your workspace within seconds.

## Supported features

| Feature | Supported | Notes |
|---|---|---|
| Create users | Yes | Assigning someone in Okta adds them to your Velt workspace as a Member, before they ever sign in. |
| Update user attributes | Yes | Okta sends profile changes and reactivations to Velt. |
| Deactivate users | Yes | Unassigning or deactivating someone in Okta removes them from the workspace right away. |
| Roles from Okta | No | Change a member's role in Velt under **Team → Users**. |
| Group push, password sync | No | Velt doesn't create groups from Okta, and the Velt Console has no passwords. You can still assign an Okta group to the app; Okta syncs its members one by one. |

## Prerequisites

- **Okta sign-in set up.** Finish [Okta Sign-In (SAML)](/security/okta/saml-sign-in) first. The sync settings appear in Velt once your SAML configuration is saved.
- **Okta Lifecycle Management** on your Okta plan.
- **An Okta admin account** that can edit app provisioning (Super Administrator or Application Administrator).
- **Owner access to your Velt workspace.** Only the workspace owner sees **Team → SAML 2.0** in the Velt Console.

## Setup

<Steps titleSize="h2">

<Step title="Create a sync token (in Velt)">

In the [Velt Console](https://console.velt.dev), go to **Team → SAML 2.0 → 4. Automatic user sync (SCIM)** and click **Turn on and create token**. Copy the token from **Your SCIM token**.

<Warning>
Velt shows the token once. Treat it like a password and paste it only into Okta. If it's lost or shared, create a new one: that stops the old one right away.
</Warning>

</Step>

<Step title="Connect Okta to Velt (in Okta)">

1. Open the Velt app → **Provisioning** tab → **Configure API Integration**.
2. Tick **Enable API integration**.
3. Paste the token into **API Token**.
4. Click **Test API Credentials**. Okta confirms the app was verified.
5. Click **Save**.

Velt doesn't use Okta groups, so **Import Groups** can be on or off.

</Step>

<Step title="Choose what Okta sends to Velt (in Okta)">

Under **Provisioning → To App**, click **Edit** and turn on:

| Setting | Value |
|---|---|
| **Create Users** | On. If **Set password when creating new users** appears and is on, turn it off. |
| **Update User Attributes** | On |
| **Deactivate Users** | On |

Click **Save**.

</Step>

<Step title="Assign people (in Okta)">

On the **Assignments** tab, click **Assign → Assign to People** or **Assign to Groups**, then **Save and Go Back → Done**. Okta adds each person to Velt within seconds. If people you assigned before turning on sync don't appear in Velt, unassign and assign them again.

</Step>

<Step title="Check the result (in Velt)">

**Team → Users** lists everyone Okta added. On **Team → SAML 2.0 → 4**, the status shows **On**, the last four characters of your token, and when Okta last connected.

</Step>

</Steps>

## What Okta changes in Velt

| In Okta you... | In Velt |
|---|---|
| Assign someone, or add them to an assigned group | They're added to the workspace as a Member. Nothing changes if they're already a member. |
| Change their profile | Okta sends the change to Velt. |
| Unassign them, remove them from the assigned group, or deactivate them | They're removed from the workspace right away, and signed out if it was their only Velt workspace. |
| Reactivate or reassign them | They're added back. |
| Unassign the workspace owner | Nothing. Sync never removes the owner. |

Good to know:

- Only emails on your workspace's **Email Domain** are synced.
- People who are already in the workspace keep their role.
- Velt doesn't email the people sync adds. They sign in from the Velt tile in Okta or from your [sign-in page](/security/okta/saml-sign-in#signing-in-from-velt).

## Making changes

- **Replace the sync token:** on **Team → SAML 2.0 → 4**, click **Create a new token** and confirm; the old one stops working right away. In Okta, go to **Provisioning → Integration → Edit**, paste the new token into **API Token**, click **Test API Credentials**, then **Save**.
- **Turn user sync off:** click **Turn off** and confirm. Okta can no longer add or remove anyone, and current members stay.

## Troubleshooting

| What you see | What to do |
|---|---|
| **Test API Credentials** fails in Okta | Check that sync is **On** in Velt and that you pasted the whole token, which starts with `vscim_`. If you created a new token since, paste the newest one. |
| No **4. Automatic user sync** section in Velt | Save your SAML configuration first (see [Okta Sign-In (SAML)](/security/okta/saml-sign-in)). Only the workspace owner sees the section. |
| No **Provisioning** tab in Okta | Your Okta plan may not include Lifecycle Management. Invite people in Velt under **Team → Users** instead. |
| Someone you assigned isn't in Velt | Their email isn't on your workspace's Email Domain, or **Create Users** is off under **To App**. Okta lists failed pushes under **Dashboard → Tasks**, where you can retry them. |
| Someone you removed can still open Velt | They're a member of another Velt workspace. Sync only removes them from this one. |
| A role you changed in Okta doesn't show in Velt | Roles aren't synced. Change it in Velt under **Team → Users**. |
| Some pushes fail while you assign a very large group | Velt accepts up to 600 changes a minute per workspace. Wait a minute, then retry the failed tasks in Okta. |
