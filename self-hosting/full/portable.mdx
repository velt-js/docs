<Note>
  The Portable backend is in **closed beta**. Contact us to request access.
</Note>

Full self-hosting is generally available on GCP plus Firebase today. The Portable backend is a second option we're building with design partners: it replaces Firebase with a gateway you deploy on your own infrastructure, backed by Postgres and Redis, so a deployment can run with **no Firebase dependency**. We grant access case by case rather than self-serve.

## How it's different from GCP full self-hosting

| | GCP full self-hosting | Portable |
| --- | --- | --- |
| **Data plane** | Firestore / RTDB | Postgres + Redis, in your own Kubernetes cluster |
| **Cloud** | Google Cloud | Any cloud you deploy your gateway to |
| **SDK config** | `config.selfHosted` pointed at your GCP-hosted backend | `config.selfHosted.portableBackendUrl` pointed at your own gateway |
| **Status** | Generally available | Closed beta |

The [core concepts](/self-hosting/full/overview#core-concepts) on the overview page, like strict mode and the signed manifest, still apply. Only the backend architecture changes.

## What's available today

- [Get Started on GCP](/self-hosting/full/gcp/overview) is the generally available path. If your team can deploy into a GCP project, you can run the full stack now.
- [Overview](/self-hosting/full/overview) covers the concepts that apply to every deployment.

## Request access

Contact us to join the closed beta. Include the following so we can tell you where you land in the queue:

- Why Firebase is a blocker for your deployment (for example, an air-gapped or regulated environment).
- Target infrastructure: cloud, region, and whether Kubernetes is already available to you.
- Rough scale: number of end users, documents, and expected concurrency.
- Whether a GCP deployment would unblock you in the meantime.
