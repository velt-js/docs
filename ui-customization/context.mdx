**Context** is arbitrary, customer-defined key-value metadata you attach to a comment/annotation when it's created. Velt stores it on the annotation (`annotation.context.*`), it survives round-trips, and your wireframes can read it. It's the bridge between **your app's domain** (a form question, an invoice line, an email block) and **Velt's comment UI**, and it's how you **scope a comment to a specific element** on the page.

<Note>
Context values are read in wireframes with the token syntax (`{annotation.context.*}`, `velt-if`, `velt-data`). New to tokens? Read [Template Variables](/ui-customization/template-variables) and [Conditional Templates](/ui-customization/conditional-templates) first. "Page mode" below means the comments sidebar anchored next to specific elements on your page.
</Note>

This is a core customization concept: if your design shows app-specific info in the comment UI (a question title in the dialog header, a "jump to this row" button, a per-element comment), context is how you get that data in.

## Attach context

Every method below lands on the same place, `annotation.context`, so wireframes read them all the same way. Pick by **when you know the value**:

| Method | Use when |
|---|---|
| [`context` prop](#the-context-prop) | You know the value when you render the component. The common case. |
| [`setContextProvider()`](#setcontextprovider) | The value depends on the document or location, and every new comment should get it. |
| [`addContext()`](#addcontext) | The value is only known at the moment the comment is created. |
| [`updateContext()`](#updatecontext) | The comment already exists and its context changed. |
| [`setContextInPageModeComposer()`](#setcontextinpagemodecomposer) | You're driving the page-mode composer yourself. |

Full API detail for all five, including params and merge behavior: [Metadata](/async-collaboration/comments/customize-behavior#metadata).

### The `context` prop

Pass your object on the component that creates the comment. `VeltCommentTool`, `VeltCommentBubble`, `VeltCommentPin`, `VeltCommentComposer`, and `VeltInlineCommentsSection` all accept it, along with the sidebar and dialog components (full list: [`Props`](/ui-customization/reference/props)).

<Tabs>
<Tab title="React / Next.js">
```tsx
const targetElementId = `question-${question.id}`;   // matches the DOM id of the element

<VeltCommentTool
  contextInPageModeComposer={true}
  targetElementId={targetElementId}                  // scopes the comment to that element
  context={{ questionId: question.id, questionNumber: question.number, questionTitle: question.title }}
/>
```
</Tab>
<Tab title="Other Frameworks">
```html
<!-- target-element-id matches the DOM id of the element -->
<velt-comment-tool
  context-in-page-mode-composer="true"
  target-element-id="question-1"
  context='{"questionId": "1", "questionNumber": 1, "questionTitle": "What is your role?"}'>
</velt-comment-tool>
```
</Tab>
</Tabs>

- **`context`**: your object (any keys). Lands on `annotation.context`.
- **`targetElementId`**: ties the comment/bubble to a DOM element with that `id`, so the bubble renders on that row.
- **`contextInPageModeComposer`**: routes this context into the page-mode composer flow.

Other domain shapes work the same: `context={{ title: step.label, scope: "step", stepId: step.id }}`, `context={{ device, mode }}`, and so on.

<Tip>
`contextOptions={{ partialMatch: true }}` changes how a component **matches** existing comments by context: with it, a comment matches when it contains all the fields you specified, ignoring extras. See [`ContextOptions`](/api-reference/sdk/models/data-models#contextoptions).
</Tip>

### `setContextProvider()`

Register a function and Velt calls it for every new comment annotation, passing the `documentId` and optional `location`. Use it when context is derived rather than known at render time, so you don't have to repeat the prop on every component.

<Tabs>
<Tab title="React / Next.js">
```tsx
// Hook
const { setContextProvider } = useSetContextProvider();
useEffect(() => {
  setContextProvider?.((documentId, location) => ({ dashboardId: documentId, view: location?.id }));
}, [setContextProvider]);

// API Method
const commentElement = client.getCommentElement();
commentElement.setContextProvider((documentId, location) => ({ dashboardId: documentId, view: location?.id }));
```
</Tab>
<Tab title="Other Frameworks">
```js
const commentElement = Velt.getCommentElement();
commentElement.setContextProvider((documentId, location) => ({
  dashboardId: documentId,
  view: location?.id,
}));
```
</Tab>
</Tabs>

The function may return an object, `null`, `undefined`, or a Promise resolving to any of those, so you can skip adding context for some documents or locations.

### `addContext()`

The `addCommentAnnotationDraft` and `addCommentAnnotation` events carry an `addContext` method. Call it to attach context at the moment the comment is created, when the value depends on something you only know then (the current scroll target, the selected row, a live filter).

<Tabs>
<Tab title="React / Next.js">
```tsx
// Hook
const event = useCommentEventCallback('addCommentAnnotation');
useEffect(() => {
  event?.addContext({ selectedRowId: getSelectedRowId() });
}, [event]);

// API Method
const commentElement = client.getCommentElement();
const subscription = commentElement.on('addCommentAnnotation').subscribe((event) => {
  event.addContext({ selectedRowId: getSelectedRowId() });
});
subscription?.unsubscribe();
```
</Tab>
<Tab title="Other Frameworks">
```js
const commentElement = Velt.getCommentElement();
const subscription = commentElement.on('addCommentAnnotation').subscribe((event) => {
  event.addContext({ selectedRowId: getSelectedRowId() });
});
subscription?.unsubscribe();
```
</Tab>
</Tabs>

### `updateContext()`

Change the context on a comment that already exists, for example when the dashboard it lives on gets renamed. Pass `{ merge: true }` to patch the existing object; the default replaces it entirely.

<Tabs>
<Tab title="React / Next.js">
```tsx
// API Method (no hook)
const commentElement = client.getCommentElement();
commentElement.updateContext(annotationId, { questionTitle: newTitle }, { merge: true });
```
</Tab>
<Tab title="Other Frameworks">
```js
const commentElement = Velt.getCommentElement();
commentElement.updateContext(annotationId, { questionTitle: newTitle }, { merge: true });
```
</Tab>
</Tabs>

### `setContextInPageModeComposer()`

When a comment tool is clicked, Velt fires a `commentToolClick` event carrying that tool's `context` and `targetElementId`. Push it into the shared page-mode composer, then focus it.

<Tabs>
<Tab title="React / Next.js">
```tsx
// Hook
const commentUtils = useCommentUtils();
const evt = useCommentEventCallback('commentToolClick');
useEffect(() => {
  if (commentUtils && evt) {
    commentUtils.setContextInPageModeComposer({ context: evt.context, targetElementId: evt.targetElementId });
    commentUtils.focusPageModeComposer();
  }
}, [evt]);

// after submit / on cancel:
commentUtils.clearPageModeComposerContext();
```
</Tab>
<Tab title="Other Frameworks">
```js
const commentElement = Velt.getCommentElement();
const subscription = commentElement.on('commentToolClick').subscribe((event) => {
  commentElement.setContextInPageModeComposer({ context: event.context, targetElementId: event.targetElementId });
  commentElement.focusPageModeComposer();
});

// after submit / on cancel:
commentElement.clearPageModeComposerContext();
subscription?.unsubscribe();
```
</Tab>
</Tabs>

The three methods here are `setContextInPageModeComposer({ context, targetElementId })`, `focusPageModeComposer()`, and `clearPageModeComposerContext()`. Under the hood this is the `context` argument of `addComment(...)`. To get the tool's context into the composer automatically instead, set `contextInPageModeComposer` on the tool ([above](#the-context-prop)).

## Read context in the wireframe

Context is readable via `{…}` tokens: display with `<VeltData field="…">`, branch with `<VeltIf condition="…">`. **The path prefix depends on the surface:**

| Where you're reading it | Path prefix |
|---|---|
| Comment dialog | `annotation.context.<key>` (also `commentAnnotation.context.<key>`) |
| Page-mode composer (live, not yet saved) | `context.<key>` |
| Sidebar focused thread | `focusedAnnotation.context.<key>` |
| Notification list item | `notification.notificationSourceData.context.<key>` (or `notification.metadata.<key>`) |

```tsx
// custom dialog header: only when the context key exists
<VeltIf condition="!{pageModeComposer} && {annotation.context.questionTitle}">
  <VeltButtonWireframe type="button" id="navigate-to-question-button">
    <VeltData field="annotation.context.questionNumber" />. <VeltData field="annotation.context.questionTitle" />
  </VeltButtonWireframe>
</VeltIf>

// composer header echoing the active context while composing (bare context. path)
<VeltIf condition="{pageModeComposer} && {context.questionTitle}">
  <VeltData field="context.questionTitle" />
</VeltIf>
```

> The custom `id="navigate-to-question-button"` button is wired to app behavior via the `veltButtonClick` bridge ([`Patterns and tips`](/ui-customization/patterns-and-tips)): e.g. scroll to the question.

## What context enables

1. **Scope a comment to a specific element**: `targetElementId` + a matching DOM `id` (e.g. `question-${id}`); a `<VeltCommentBubble targetElementId=…>` then renders that element's bubble in place.
2. **Show app metadata in the comment UI**: question title/number in the header, an invoice line label, an email device/mode badge: straight off `annotation.context.*`.
3. **Conditional UI by domain type**: branch the wireframe on context, e.g. `velt-class="'is-action': {annotation.context.commentType} === 'action'"` or `velt-if="{annotation.context.type} === 'ApproverComment'"`.
4. **Deep-linking / navigation**: a "jump to" button that exists only when a context key is present, handled via `veltButtonClick`.

## Checklist

- [ ] Attached context by the method that matches when you know the value (prop, provider, create event, update, or page-mode composer).
- [ ] Read it with the correct path prefix for the surface (`annotation.context.*` in the dialog, `context.*` in the page-mode composer, `focusedAnnotation.context.*` in the sidebar).
- [ ] Gated context-dependent UI with `velt-if="{…context.key}"` so it only shows when present.
- [ ] Cleared page-mode context after submit/cancel (`clearPageModeComposerContext()`).
